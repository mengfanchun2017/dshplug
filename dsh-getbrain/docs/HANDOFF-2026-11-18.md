### 2.2 「发芽」平台只能查，不能生成

我逐个探过 14 个端点：

- `GET /resource/note/sprout?id=<note_id>` → **200**，返回 `{sprout, has_sprout}`
- `POST /resource/note/sprout` → **404**
- `/resource/ai/sprout`、`/resource/ai/ask`、`/resource/note/ask` 等 13 个 → **全部 404**

所以要平台侧发芽，只能在得到 App 里点。本插件做的是：取素材 + 可改提示词 + 交给会话里的 AI。

### 2.3 你的库不是"一个知识库"，是两堆东西

实测：

| | 数量 | 占比 |
|---|---|---|
| 课程划线摘录（`ref`/`class_audio`/`link`/`book`） | 4053 | **94%** |
| 你自己的记录（`audio`/`meeting`/`internal_record`/`plain_text`…） | 269 | **6%** |

## 5. 还差什么（诚实清单）

1. **删笔记没接进面板** —— 故意不做。`note_delete` 平台侧可能不进回收站（官方 FAQ 自列此 bug）。
2. **撤销不能还原正文** —— 只还原归属（库/标签）。要还原正文得存全文，体积大 3 个数量级。
3. **context-pack 没有语义检索** —— 靠关键词命中，不是 embedding。同义不同词（"沟通" vs "交流"）会漏。
4. **siblings 经常是 0** —— 很多录音类笔记的"课程"就是它自己。这是数据形状，不是 bug。
5. **渐进式总结 Layer 2–4 还没有** —— 这是理论上最该做的（加粗/高亮/用自己的话），需要写回笔记能力，属下一阶段。

## 8. 补记：界面接撤销时抓出的三个真 bug（2026-11-18 17:1x）

上一轮我说“可回退已实装”——其实后端通了，**界面根本没入口**。这一轮把它接上，并抓出三个真 bug：

| # | bug | 后果 | 如何发现 |
|---|---|---|---|
| 1 | `renderUndo` 读 `undo.data.list`，实际结构是 `{phase, list}` | 即使有批次也永远显示“没有可撤销”，**静默失效** | 用桩 fetch 返回 2 条批次，渲染后文本里找不到文件名 |
| 2 | 没计划时 `renderApply` 直接 return | 刚写完计划被消费 → 撤销区不显示 → “写完了不能回退” | 点「确认执行」后发现没有 `/undos` 请求 |
| 3 | `setUndos` 定义在 `runApply` 之后 | TDZ：一点真写就报错（闭包延迟求值，静态检查看不出） | 按声明行号排序对不上 |

另外补了一个体验缺陷：真写成功后不刷新撤销列表，用户以为“刚写的也不能退”。

**验证方式**（不是读代码，是跑组件、点按钮、看输出）：

四个渲染场景均用桩 fetch + 带状态的 React 替身真实执行：

```
PASS  有 open 批次       → 显示文件名/条数/干跑/我要撤销
PASS  无批次             → 显示“没有可撤销的批次”
PASS  只有已撤销         → 显示历史列表，不给按钮
PASS  open+已撤销并存   → 同时显示两者
```

后端两条按钮路径也各跑了一遍（真笔记 `1927331041815714728`）：

```
干跑：补回库 0 / 移出库 1 / 补标签 0 / 删标签 0；跳过 0
dry-run 不修改撤销记录状态。

真撤销：同样移出 1 个库
→ status 变 undone，undone_at = 2026-11-18T17:13:02+08:00
```

> 教训：后端有函数不等于用户能用。“可回退”这个需求，到“页面上有一个按钮且点下去真的能把东西改回去”才算完。
