# 资产契约

这份文档定义「一个像素 IP 标记算合格」的标准。导出器按它生成，评审按它验收。

---

## 1. 网格

原生网格 **48 × 48**。所有绘制都发生在这个整数格上，没有小数坐标、没有抗锯齿。

为什么是 48：能整除 16 和 24（小尺寸图标族），四档整数放大后正好落在常用尺寸上，且 48 本身在 100% 缩放下仍然可读。

---

## 2. 放大档位

| 档 | 尺寸 | 典型用途 |
|---|---|---|
| ×1 | 48 | 原生、设计源 |
| ×2 | 96 | 应用内图标 |
| ×3 | 144 | 头像小档 |
| ×4 | 192 | PWA / Android |
| ×5 | 240 | 中等展示 |
| ×6 | 288 | 中等展示 |
| ×8 | 384 | 演示文稿 |
| ×10 | 480 | 大图展示 |
| ×16 | 768 | 印刷预备 |
| ×21 | 1008 | 印刷主档 |

规则：**只允许整数倍**。每个源像素变成一个 `scale × scale` 的实心块，采样方式是最近邻。任何非整数倍尺寸都不在契约内——插值会造出半透明边缘，那就不是像素画了。

512 是特例：它是 480 居中放在 512 画布上（四周各留 16 px 透明），为了满足社交平台/商店要求的正方形画布，不是为了放大。

---

## 3. 小尺寸重绘

16 / 24 / 32 / 64 px **不是缩小版**，是按各自网格重新画的。

48 px 的细节缩到 16 px 会糊成一团：1 px 的描边变成 1/3 px，识别不出来。所以小尺寸另起一张网格，减少细节、加粗轮廓、只保留剪影特征。

64 px 缺档是有意的：48 × 4/3 不是整数。要么重画一张 64 的，要么就不提供——不能靠插值凑。

---

## 4. 调色板

8 色，见 `assets/palette.json`：

| 名 | 值 | 用途 |
|---|---|---|
| Ink | `#071321` | 最深，轮廓/眼睛 |
| Deep water | `#112A46` | 背光面 |
| Mid water | `#1A4670` | 主体暗部 |
| Manta blue | `#2A6C9C` | 主体（品牌主色） |
| Shallow water | `#50A0C6` | 受光面 |
| Bubble | `#AAE9EE` | 高光 |
| Foam | `#FAFDFF` | 最亮 |
| Coral | `#FF8AA4` | 强调（腮红，克制使用） |

规则：整档资产只用这 8 色。加色要同时改 `palette.json`、`palette.png` 和示例作品，否则再生成会漂移。

---

## 5. 留白

标记四周至少留 **1 个原生像素**（48 网格下即 48 px 图里的 1 px）透明边。理由：贴边在深色/浅色底上都会被裁掉一部分，而且圆角容器会啃掉角落。

512 社交画布留 16 px，是同一规则在大画布上的换算（10 倍档的一半留白）。

---

## 6. 命名

```
<slug>-<边>px.png       例如 manta-mark-48.png
```

`slug` 由 Client 半在导出时附在文档上（`BRAND.slug`），宿主半只负责拼名字，不发明前缀。

再导出**覆盖同名文件**，不产生 `-2` `-3` 变体——整档是可以从主网格完整重建的，版本历史归 Git 管，不归文件名管。

---

## 7. 验收清单

- [ ] 每个尺寸都是原生网格的整数倍（或小尺寸手绘档 / 512 画布）
- [ ] 没有半像素、没有插值边缘、没有抗锯齿
- [ ] 只用调色板里的 8 色
- [ ] 四周有透明留白
- [ ] 16 px 下仍能认出剪影
- [ ] 深底浅底都看得到（描边足够）
- [ ] `node test/run.mjs` 通过
