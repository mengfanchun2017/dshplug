# dshplug · 归档区（archive）

这里存放**已经完成、暂不继续开发**的插件开发记录。
不是可加载的插件目录（`install.ps1` 不会读这里），是**给人看的项目档案**。

## 每个归档目录的固定结构

```
archive\<插件名>\
├─ README.md              ← 入口：这是什么、决策记录(ADR)、机制备忘、恢复步骤、立下的规则
├─ DEVELOPMENT-LOG.md     ← 开发过程复盘（流水细节，可很长）
├─ source\                ← 最后一次的源码快照，可直接放回插件目录继续开发
├─ packages\              ← 可安装产物（.tgz / .zip / MANIFEST）
├─ tools\                 ← 与本案绑定的脚本（打包、诊断、证据提取）
└─ reference\             ← 平台侧证据摘录（源码片段、文档摘录）
```

`README.md` 必须能独立回答三个问题：
1. **这是什么、当时为什么这么做**（ADR）
2. **怎么跑起来 / 怎么继续改**（恢复步骤 + 验证命令）
3. **有哪些坑已经踩过**（机制备忘 + 遗留事项）

---

## ⚠️ 重要：`packages\` 里的产物**不进 git**

仓库根 `.gitignore` 有这几条：

```gitignore
*.zip
*.tgz
*.tar.gz
MANIFEST.txt
dist/
```

所以 `archive\*\packages\` 下的 `.zip` / `.tgz` **只存在于本机**，`git clone` 到另一台机器**拿不到**。
但 `*.MANIFEST.txt` **会**入库（根忽略规则写的是 `MANIFEST.txt`，只匹配同名文件）——这是故意的：哈希清单跟 git 走，才知道该传哪个包。

**要跨机带走产物，必须手动传压缩包**（U 盘 / 网盘 / 直接拷贝）。
源码、文档、工具、决策记录、以及 MANIFEST 哈希清单则完全跟着 git 走，不受影响。

## 归档规则（自 2026-11-12 起）

1. **只归档「完成」或「暂停」的插件**。仍在活跃开发的放在仓库根目录，别进 archive。
2. **归档 = 冻结**。归档后再改代码，要么回到根目录新建开发目录，要么明确在 README 顶部写
   「本归档已解冻，继续开发见 <路径>」。
3. **归档前必须**：
   - 跑通 `verify`（离线自检全绿）
   - 记录产物哈希（写进 `README.md` 与 `packages` 旁的 MANIFEST）
   - 确认 `git status` 干净，再复制源码
4. **归档不删原件**。工作区里的插件目录在确认归档完整之前不要删；删之前用文件哈希逐一比对。
5. **一个插件一个目录**，目录名 = 插件目录名（不是包名）。
6. **版本号写死**，写清「最后一次验证时的版本」，不写「最新版」。
